# Relic of the Past v0.19.0

Three studios in one release: one for the game's text, one for its audio, and one for the player sprite. Sprite extraction also works again, which it had not since v0.17.0.

## Sprite extraction is fixed

- Extracting sprites from a ROM produced nothing at all in v0.17.0, v0.17.1 and v0.18.0. It reported success and wrote zero files, which is why it looked like it had simply found nothing.
- The cause was on our side, not yours: the extraction data stopped being included in the published builds. Nothing was wrong with your ROM and nothing needs reimporting.
- If you extracted sprites on v0.16 or earlier and pressed Extract again on a later version, your extracted sprites were deleted. Extract once more on this version and they come back.
- The release now refuses to build at all if that data is missing, so this cannot recur quietly.

## Language Studio

- Language packs are now editable language sets, not just something you extract and use: the dialogue, a glossary, and the pause menu name table, all stored as plain files you can keep and share.
- The dialogue editor works a line at a time, the way the text box actually does, with a gutter showing the row, how many pixels are still free, and the character count.
- Every character is measured with its real width from the language pack, so what you see is the width the game will draw.
- The game never wraps a line and never checks whether one fits, so an overlong line paints over the line below it. The editor will not let you save while any row overflows.
- Waits and row breaks appear as markers in the margin rather than tags mixed into your text.

## Audio replacement, everywhere

- Replacement audio is no longer just music. Ambient beds and sound effects can be replaced per sound, and anything a pack does not claim keeps playing from the game as normal.
- A new layered pack format (`.msul`) with a studio for building and previewing them, and configuration read from the pack files themselves.
- You can listen to the original next to your replacement. It plays on a separate sound chip, so nothing about the running game or your next save is affected.
- Every sound in the game is listed with a plain-language name.
- Music now changes when it should. Crossing between two areas that shared the same original track was silent about the change, so per-area tracks never played. Entering a building, loading a save state, and respawning after a death each had their own gap; a respawn in particular could carry the music from the door you used before you died.

## Player Sprite Studio

- The player sprite panel is now a studio covering every state the game can draw the player in: 40 actions across their facings, viewable as a gallery.
- Palette editing for the four outfits and both glove colours, snapped to the colours the console can actually display. Your changes are kept as a layer over the original, so Revert is exact.
- Import and export community `.zspr` sheets, with a byte-for-byte round trip.
- A new `.rsp` pack keeps both the sheet and your recolour together, so a palette edit survives saving and reopening.
- Create a new sprite starting from the game's own player sheet, read out of your ROM.

## Saves and profiles

- A new Import Save button on the Home tab brings a battery save from another emulator (such as a Snes9x `.srm`) into a profile. It is checked against the game's own save checksum before anything is written, and tells you plainly either way.
- Deleting a custom sprite now clears it from every profile that had it selected, instead of leaving the setting pointing at a file that no longer exists. If the running game was wearing it, it goes back to the original sprite.

## Fixes

- The running man in the village can now outrun a wide view. His sprint was a fixed set of frames tuned to end just past the original screen width, so on a wider view he stopped short of the fence, and he could pause partway if you did not follow him.
- The mute control is now the single thing that decides whether there is sound. Volume reaches the game two ways, and only one of them was being set, which could leave audio playing behind a control that read as muted.
